# Copilot 审查强度审计器

[English](README.md) · 支持 [iPolloWork](https://github.com/Devin-AXIS/iPolloWork)

Copilot 审查强度审计器是一个可复用 Skill，用于判断请求、拉取请求、用户、仓库、组织和 GitHub 内置设置重叠时，GitHub Copilot 代码审查最终采用哪一种强度。它会生成证据链、切换影响图、可辩护的 AI credits 区间和受控验证计划，但不会修改 GitHub 设置。

## 解决的问题

Copilot 代码审查强度并不由单个仓库开关决定。请求时明确选择的强度、同一 PR 之前采用的强度或请求者个人设置，都可能优先于仓库和组织默认值。只查看仓库设置的资产清单，可能同时误判审查深度和预计消耗。

本 Skill 会沿完整优先级链逐步判断；若较高优先级值未知，就停止并保留未知，而不是直接采用下一级设置。它还会把已确认合计与规划情景分开，适合管理员和工程负责人在调整默认值或预算前获得可审计结论。

## 适用人群

- 评估 Copilot 代码审查默认值的 GitHub 组织所有者。
- 为自动审查选择 Lite 或 Balanced 的仓库管理员。
- 需要估算 AI credits 暴露范围、但不希望编造单点预测的 FinOps 与平台团队。
- 核对关键变更是否获得预期审查深度的安全和质量团队。
- 需要区分配置推测与实际审查运行证据的审计人员。

## 使用场景

- 找出 `Default` 可能解析为 Balanced 的仓库。
- 解释为什么手动请求或同一 PR 的历史强度会覆盖较低层默认值。
- 保留有意设置的仓库 Lite，同时指出尚未确认的请求者行为。
- 计算已确认的月度区间，并单独列出未知案例的情景包络。
- 在大范围修改配置前设计带可观察回滚信号的试点。
- 将预测强度与 Copilot 审查概览中显示的实际强度进行核对。

## 核心功能

- 将设置规范化为 `Lite`、`Balanced`、`Default`、`none` 或 `unknown`。
- 跟踪六级优先顺序，并指出明确赢家或阻塞性未知项。
- 记录被忽略的低优先级设置。
- 区分切换暴露、显式保护、高优先级保护和无法确定的案例。
- 只使用输入中的审查量和成本区间；未解决案例不进入已确认合计。
- 生成限定管理员权限范围的行动计划、验证数据请求和回滚信号。
- 保留人工复核要求，并明确未改变外部状态。

## 完整流程

1. 导出或抄录适用的请求、PR、请求者、仓库和组织强度设置。
2. 补充所有权类型、触发方式、审查量、变更类型、适用日期和已知成本估算。
3. 不适用的设置标为 `none`，尚未收集的设置标为 `unknown`。
4. 调用 Copilot 审查强度审计器，并要求生成完整审计格式。
5. 解决所有阻塞性未知项后，才能把低层默认值视为实际生效值。
6. 在代表性仓库试点，记录每次审查显示的强度，并将实际消耗与估算分开比较。
7. 根据回滚信号扩大策略范围，或恢复事先记录的旧值。

## 前置条件

- 包含强度设置的文本或表格清单；仓库内示例可直接用于演练。
- 能说明相关作用域和日期下 `Default` 行为的已核验产品规则。
- 若需要资产组合区间，还需提供审查次数和成本估算。
- 若使用安装包路线，需要一个已配置模型引擎的 iPolloWork 本地项目。

Skill 本身不需要 GitHub Token、账号连接、网络访问、脚本运行时或外部服务。

## 输入与输出

**输入：** 一个或多个案例，包括触发类型、请求时明确强度、同一 PR 历史强度、请求者设置、仓库设置、组织或所有者设置、内置默认规则、所有权类型、审查量和成本假设。

**输出：** Markdown 审计报告，包含结论、逐案例解析表、证据路径、被忽略设置、暴露标签、已确认区间和情景区间、行动计划、验证查询、回滚信号及建议边界。

缺失证据会得到 `unknown`，不会被悄悄当作 `none`。

## 端到端示例

[`examples/effort-audit-packet.md`](examples/effort-audit-packet.md) 提供 7 个组织仓库案例，设置存在重叠。可以这样请求：

```text
使用 Copilot 审查强度审计器审计这个数据包。返回完整解析表、已确认月度区间、切换影响图、最小扰动行动计划、验证查询、回滚信号和建议边界。
```

[`examples/expected-audit.md`](examples/expected-audit.md) 中的预期报告可确认一次显式 Balanced 请求、一次历史 Lite 运行和一次请求者 Balanced 选择。另有 4 个案例因为请求者 `Default` 的行为未定义，或较高优先级值缺失而保持未知。已确认月度估算与全 Lite/全 Balanced 情景包络分开列示。

## 在 iPolloWork 中安装与使用

1. 打开 GitHub Release，下载 `copilot-review-effort-auditor-1.0.0.ipollowork-plugin`。
2. 在 iPolloWork 选择 **扩展 → 插件 → 添加 → 文件**，选择下载的文件。
3. 确认发布者为 `sykdhqk`、版本为 `1.0.0`、包含 1 个 Skill，且没有 Agent、命令或 MCP 资源，然后安装。
4. 保持插件和 `Copilot Review Effort Auditor` Skill 均为启用状态。
5. 打开本地项目并新建任务，使该任务加载新安装的 Skill。
6. 粘贴或附加审查强度清单，并使用上面的示例请求。
7. 检查每个案例是否给出获胜优先级或阻塞性未知项，成本是否区分已确认与情景，并以建议边界结束。
8. 保存或导出 Markdown 审计报告。获批的 GitHub 修改需另行通过仓库或组织控制界面执行。

如需使用独立 Skill 包，解压 `copilot-review-effort-auditor-1.0.0-skill.zip`。在 iPolloWork 本地 Skill 导入页面选择直接包含 `SKILL.md` 的文件夹，并按提示重新加载。不要选择 ZIP 或仓库根目录。

### 排错

- 若无法选择安装包，确认扩展名为 `.ipollowork-plugin`。
- 若预览没有显示 1 个 Skill，重新下载 Release 产物并核对 `SHA256SUMS.txt`。
- 若任务没有加载 Skill，确认资源已启用，并在安装后新建任务。
- 若结果在较高优先级为 `unknown` 时仍选择仓库值，要求输出完整证据路径，并保留该项为未知。

## 功能限制

- Skill 只审计提供的证据，不会从 GitHub 读取组织设置或审查元数据。
- 若输入没有给出已核验规则，它无法判断某作用域下未文档化的 `Default` 行为。
- 成本区间来自输入估算，不包含输入未量化的成本组成。
- 它不会修改策略、预算、拉取请求或审查行为。
- Balanced 并非自动适用于所有仓库；应结合变更关键程度、延迟和预算约束选择强度。
- Copilot 反馈仍可能遗漏问题或产生错误，必须由人工复核。

## 常见问题

**为什么 `unknown` 与 `none` 不同？**  
`none` 表示该优先级不适用；`unknown` 表示可能存在一个会覆盖所有低层设置的值。

**仓库 Lite 能覆盖手动 Balanced 请求吗？**  
不能。显式请求在输入提供的优先顺序中更靠前。

**同一 PR 之前的 Lite 会影响重新审查吗？**  
可能会。输入中的顺序把同一 PR 的历史强度放在请求者、仓库和组织设置之前。

**这份报告能预测账单吗？**  
不能。它只应用输入提供的区间和审查量，标明情景，并将其他使用成本排除在合计之外。
